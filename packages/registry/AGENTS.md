# Registry

Git-based Module and template registry: resolve, fetch, and cache from local workspace, GitHub, or npm.

**Parent:** repository root [`AGENTS.md`](../../AGENTS.md) owns change protocol, Module integrity (_frozen_ lock), TypeScript, security, product language, testing, and commit gates. This guide owns local mechanics only. The parent Module integrity gate is authoritative for when and how to prove the lock.

## Change protocol

1. **Route.** Read the parent guide (especially Module integrity) and this file.
2. **Implement** using the local patterns below. Any change that alters resolved Module state must regenerate and commit `apps/registry/registry.lock.json` in the same _slice_.
3. **Verify.** Focused package tests while iterating. Full pre-commit gates live in the parent guide. After `modules/` changes (or lock/resolver changes that affect the lock), prove `bun run generate:modules -- --frozen` from repo root.
   - Done when the _frozen_ lock check and every other required parent gate for the _slice_ are _green_.

## Structure

```
src/
  index.ts          Public API re-exports
  types.ts          Zod schemas + TypeScript types (manifest, specifier, config)
  specifier.ts      Parse module specifier strings into structured objects
  resolver.ts       Resolve config → concrete module list (local, registry, GitHub, npm)
  fetcher.ts        Download modules from GitHub tarballs or npm (with retry + integrity)
  manifest.ts       Build registry.json from local modules/ and templates/ directories
  lockfile.ts       Lock file (apps/registry/registry.lock.json) generation, reading, and verification
  template.ts       Resolve and fetch templates (local, registry, GitHub, npm)
  config.ts         Read and normalize store config.json
  __tests__/        Tests covering resolver, fetcher, lockfile, and related modules
```

## Module specifier formats

```
"products"                            → official (local or registry)
"@86d-app/products"                   → official (local or registry)
"github:owner/repo/modules/custom"    → GitHub subpath
"github:owner/repo/path#v2.0"         → GitHub with ref
"npm:@acme/module"                    → npm package
"npm:@acme/module@^1.0.0"             → npm with version
```

## Config format

```json
{
  "modules": "*",
  "template": "brisa",
  "registry": "https://...registry.json",
  "moduleOptions": { "@86d-app/cart": { "maxItemsPerCart": 50 } }
}
```

- `modules: "*"` or omitted → all local workspace modules + registry modules
- `modules: [...]` → explicit list with missing-module warnings
- `template` → local name, `github:owner/repo/templates/custom`, or `npm:@acme/theme`

## Key functions

- `parseSpecifier(raw)` → `ModuleSpecifier` (source, name, packageName, repo, path, ref)
- `resolveModules(config, { root, manifest? })` → `ResolvedModule[]`
- `fetchModule(spec, root, manifest?)` → `FetchResult` (GitHub/npm download)
- `getModuleDependencies(name, manifest)` → `string[]` (transitive, topologically sorted; throws on cycles)
- `detectCircularDependencies(manifest)` → `string[]` (cycle descriptions; empty if acyclic)
- `generateLockfile(resolved, root)` → `Lockfile`
- `writeLockfile(root, lockfile)` / `readLockfile(root)` — persist/load `apps/registry/registry.lock.json`
- `verifyLockfile(lockfile, resolved)` → `LockfileDiff` (added/removed/changed)
- `isLockfileSatisfied(diff)` → `boolean`
- `resolveTemplate(spec, root, manifest?)` → `ResolvedTemplate`
- `fetchTemplate(spec, root, manifest?)` → `FetchResult`
- `buildManifest(root)` → `RegistryManifest` (scans modules/ + templates/)
- `readStoreConfig(path)` → `StoreConfig`
- `getLocalModuleNames(root)` / `getLocalTemplateNames(root)` → `string[]`
- `computeIntegrity(modulePath)` → `string | undefined`

## Registry manifest (`registry.json`)

Generated by `apps/registry/src/generate-manifest.ts`. Indexes modules and templates:
- modules: name, description, version, category, path, requires, integrity (sha256)
- modules: hasStoreComponents, hasAdminComponents, hasStorePages
- templates: name, description, version, path

Canonical published manifest is from `86d-app/86d`, not an arbitrary local copy (parent Module patterns).

## Lock file (`apps/registry/registry.lock.json`)

Generated by `internals/generators/src/generate-modules.ts`, committed to the repo. Captures exact resolved state (source, version, integrity hash, path) of every Module for reproducible builds.

- `postinstall` and GitHub Setup run `--frozen`; a stale lock fails **every** workflow in Setup
- Regenerating and committing this file is required for any Module source change, including tests
- Prove `bun run generate:modules -- --frozen` before finishing the _slice_ (parent Module integrity gate)
- Lock hashes each Module's complete source subtree, including tests, fixtures, and `package.json`

## Integration points

- **`internals/generators/src/generate-modules.ts`** — `resolveModules()` + `fetchModule()` at build time; writes the lock; supports `--frozen`; runs `detectCircularDependencies()` before generating
- **`packages/cli/src/commands/module.ts`** — `parseSpecifier`, `fetchModule`, `getModuleDependencies`, `computeIntegrity`, `getLocalModuleNames`, `readLocalManifest` for module CLI commands
- **`apps/registry/src/generate-manifest.ts`** — `buildManifest()` → `apps/registry/registry.json`
- **`apps/store/next.config.ts`** — reads generated `transpile-packages.json`

## Gotchas

- `exactOptionalPropertyTypes` is enabled — use conditional assignment for optional props
- GitHub fetching uses the tarball API with retry + exponential backoff; set `GITHUB_TOKEN` for private repos or rate limits
- npm modules install to `node_modules/`, not `modules/`; templates install to `templates/`
- Resolver checks local workspace before falling back to registry
- Fetched modules verify against sha256 hashes in the manifest
- Fetcher retries on HTTP 408, 429, 500, 502, 503, 504 and network errors
- `getModuleDependencies()` throws on circular dependencies (does not silently skip)
